# CC Switch v3.20.3

本仓库独立构建，基于官方 **3.20.2** 的 fork 迭代。只发布 **Windows x64**（MSI + 绿色版）。不构建 Linux / macOS / ARM64。

**3.20.3 的主题：Pi 接管与 Claude 对齐，且不 bump SCHEMA。** 打开 Pi 本地代理接管后，把 `~/.pi/agent/models.json` 整份投影到**现有** Claude 本地代理 listen（同一地址/端口，含 `0.0.0.0` → `127.0.0.1`）。Pi 请求走既有 Anthropic / OpenAI 路由，写入现有 `proxy_request_logs`。用量统计因此会出现这些流量；Pi 页标题栏在接管开启时会出现柱状图按钮，点一下跳到设置 → 用量。

**SCHEMA 仍为 18。** 没有 `migrate_v18_to_v19`、没有新表、没有改 `proxy_config` CHECK、没有 `app_type='pi'` 行。官方 3.20.2 能打开这个库文件，可以卸掉本 fork、装回官方版。

请从官方 3.20.2 / 本仓库 `main`（含已合并的 PR #25）升到本页 v3.20.3。

## 修复的问题

- **Pi 没法走本地代理（PR #25）。** 上游 3.20.2 里 Pi 只管理 `models.json` 供应商条目，没有接管。现在 Pi 页有与 Claude 相同的接管开关：启用后把每个 provider 的 `baseUrl` / `apiKey` 投影到 Claude 那条 listen；Anthropic / Gemini / Bedrock 写 `http://127.0.0.1:<port>`，OpenAI Completions / Responses 写 `http://127.0.0.1:<port>/v1`；`apiKey` 写成占位 `PROXY_MANAGED`。关闭接管后恢复真实上游。没有独立 Pi 端口，也没有 `/pi/<id>` 前缀。故障转移仍关闭（`supports_local_proxy()` 不含 Pi）。
- **投影必须写 `~/.pi/agent/models.json`，不是顶层 `~/.pi/models.json`。** 路径来自 `get_pi_agent_dir()`：默认 `~/.pi/agent`，可被设置覆盖或 `PI_CODING_AGENT_DIR` 改写。Windows 上 `\\wsl.localhost\<发行版>\home\<用户>\.pi\agent\` 视为合法 agent 目录。写入原子（暂存 → sha256 → 替换），未知 JSON 字段原样保留，永不碰 `auth.json`，不写 `defaultProvider` / `defaultModel`。
- **Pi 接管开了，用量却进不去、请求也不进统计。** 请求现在走同一套 handler、同一张 `proxy_request_logs`，所以用量会跳。Pi 页在接管开启时标题栏出现 BarChart2，点击跳到设置 → 用量统计（与 Claude 相同）。Pi 无法拥有独立 `proxy_config` 行，启用态写在 settings 键 `proxy_takeover_pi`；listen 复用 `Database::get_proxy_config()`（claude 行）。

## 优化

- **SCHEMA 18，可切回官方。** 启用态不进 `proxy_config`，因此不会触发官方 3.20.2 读库失败。卸掉本 fork、装回官方 3.20.2 时，SQLite `user_version` 仍是 18。settings 里多出来的 `proxy_takeover_pi` 官方会当普通键忽略。
- **与 Claude 共用 listen，不新开网关。** `0.0.0.0` 改写成 `127.0.0.1`，`::` 改写成 `::1`，和 Claude 客户端连代理的规则一致。
- **Windows-only 打包。** 沿用本 fork 的 tag 触发 Actions：只出 MSI + 绿色版。

## 自测

云端 Linux（本发版机器）按 `ci.yml` **Linux 步骤**复跑：

- `pnpm typecheck` / `pnpm format:check` / `pnpm test:unit`（135 文件 / 1090 用例）
- `cargo fmt --check` / `cargo clippy -- -D warnings` / `cargo test`（lib 2808 通过、5 忽略；另有 integration 约 127 条。含 `pi_takeover_projects_models_json_onto_claude_listen_without_schema_row`：无 `proxy_config` pi 行、`SCHEMA_VERSION == 18`、`models.json` 投影到 Claude listen、关闭后恢复、不碰 `auth.json` / settings defaults）

GitHub Actions 在本 PR 上跑了 `Frontend Checks`（已绿）。`windows-latest` / `macos-latest` / `backend-windows-wsl2` 是 **cargo 后端检查**，即使绿了也只说明单测，**不是** MSI 安装或 Tauri 窗口冒烟。PR #25 的 UNC / 未知字段 fixture 同样是临时 `$HOME`，不是用户电脑。

**云端测试 ≠ 真机 Windows 冒烟。** 发版环境没有 `wsl.exe`、没有 `\\wsl.localhost` 9P、没有 MSI 安装、没有 Tauri 窗口。本页资源是 GitHub Actions `windows-2022` 编出来的安装包，但没人在装好的 Windows 上点过接管。

v3.20.3 装上后，在 Windows 上请自己点这几下：

1. **Pi 页打开接管** — `~/.pi/agent/models.json`（或 WSL UNC 下的同一文件）里各 provider 的 `baseUrl` 应指向 `http://127.0.0.1:<Claude 代理端口>`；OpenAI 类带 `/v1`
2. **标题栏柱状图** — 接管开启后出现，点一下进入用量；发几条 Pi 请求后再看用量，应有新记录
3. **关掉接管** — `models.json` 恢复真实上游；`auth.json` 与 `settings.json` 的 defaultProvider / defaultModel 不变
4. **切回官方 3.20.2** — 同一库文件应能打开，不应出现「数据库版本过新」

任一步 FAIL：把日志贴到 issue。SCHEMA 没升，回退官方 3.20.2 是安全的。
