# CC Switch v3.20.5

本仓库独立构建，基于官方 **3.20.x**（含已合并 PR #29）。只发布 **Windows x64**（MSI + 绿色版）。不构建 Linux / macOS / ARM64。

**请优先使用绿色版（Portable）。** MSI 若在安装/升级时出现 Error 5（拒绝访问 `D:\Config.Msi` 或系统盘 `Config.Msi`），这是 Windows Installer 回滚缓存 ACL，per-user 安装包无法修复。说明见 [windows-msi-error-5-zh.md](../windows-msi-error-5-zh.md)。

**SCHEMA 仍为 18。** 没有 `migrate_v18_to_v19`、没有新表、没有改 `proxy_config` CHECK。官方 3.20.2 仍能打开这个库文件。

请从本仓库 v3.20.4（或官方 3.20.2 + 本 fork main）升到本页 v3.20.5。

## 修复的问题

- **pi_session 用时/首字显示 —（不猜时间戳）。** Pi 官方 session JSONL 只有 token/cost，没有 latency/TTFT。用量「请求日志」对 `来源=pi_session`（以及同样没有 timing 的 Claude `session_log` 等会话导入行）不再把库里的 `latency_ms=0` 渲染成假的 `0.0s`，改为 em dash `—`。SCHEMA 18 的 `latency_ms` 仍为 `NOT NULL`，导入继续写 `0`，**不会**用时间戳差值伪造耗时。Grok 等会话若真有 `api_ms > 0`、以及代理真实请求，仍显示秒数。

## 优化

- **SCHEMA 18，可切回官方。** 无库迁移。
- **Windows-only 打包。** 与 v3.20.4 相同：tag 触发只出 MSI + 绿色版。

## 自测

PR #29 tip `b305ea17` 的 GitHub Actions 全绿：

- Backend Checks (ubuntu-22.04) — pass
- Backend Checks (macos-latest) — pass
- Backend Checks (windows-latest) — pass

云端 Linux 另记：`pnpm typecheck` / `pnpm format:check` / `pnpm test:unit`（135 文件 / 1099 用例）；`cargo fmt --check` / `cargo clippy -- -D warnings`；`cargo test --lib session_usage_pi`（16 用例，含 `latency_ms=0` 且 `first_token_ms IS NULL`）。

**云端测试 ≠ 真机 Windows 冒烟。** 没有在用户电脑上点过用量页或 MSI 安装。Actions `windows-latest` / WSL2 是 cargo 检查，不是装包冒烟。

装上 v3.20.5 后请自己点：

1. 同步 Pi 会话用量 → 用量 → 请求日志。`来源=pi_session` 的用时/首字应为 `—`，不是 `0.0s`
2. Claude 会话导入行（`session_log`）同样为 `—`
3. 代理真实请求仍显示 `1.2s` / `1.2s/0.3s`
4. MSI Error 5 → 改用绿色版 zip，解压运行 `CC-Switch.exe`

任一步 FAIL：把日志贴到 issue。SCHEMA 没升，回退 v3.20.4 / 官方 3.20.2 是安全的。
