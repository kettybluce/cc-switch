# CC Switch v4.1.5

本仓库独立构建。应用内更新仍然关闭。只发布 **Windows x64**。

**不要装 v4.1.4。** 那一包没有 `READ_SCRIPT` 的 `set --` 回退：启用 Pi 供应商时若 WSL 丢掉 `$1`，会把现有 `models.json` 当成 missing，有清空 providers 的风险。

请继续使用 **v3.0.1**，等本页的 v4.1.5 MSI 就绪后再装。不要停留在 v4.1.3。

## 修复的问题

- **启用前 `files::read` 丢掉 `$1` 会把现有 `models.json` 当成 missing（v4.1.4 缺口）。** 启用「百胜」走 `switch` → read → write。v4.1.4 只给 WRITE 加了 `set --`。`READ_SCRIPT` 仍读 `$1`；空 `$1` 时 `[ ! -e "$1" ]` 当成 missing，再 write 可能清空旧供应商。v4.1.5 给 read 补了同样的 `set --`（来自 PR #19）。
- **检测代理 toast 与 Settings 绿灯打架。** Settings 已显示 `http://127.0.0.1:15721` 可达（镜像网络），「检测代理」却 toast `no route from WSL 'Ubuntu-22.04' to CC Switch on port 15721 (tried 127.0.0.1, 172.30.213.1, 10.255.255.254)`。探测与 toast 现用同一规则：本机任意 HTTP 1xx–5xx（含 `/` 上的 **404**）即成功。`172.30.213.1` / `10.255.255.254` 被拒绝只是回退。
- **启用 Pi 供应商时空 bash。** `writing Pi models.json … /bin/bash: line 1: '': No such file or directory`。现用 `wsl.exe -e bash`，拒绝空脚本，write 用 `set --` 补回 `$1`。
- **Codex / Claude / Pi 在根目录 mktemp。** `"$dir/.cc-switch-XXXXXX"` 在 `$dir` 为空时变成 `/.cc-switch-XXXXXX`。原子写改为在 `$TMPDIR` 或 `/tmp` 下 `mktemp`。空目标报 `empty-target`。
- **代理未开的 toast。** Windows 单独打 `/ping` 不再和 WSL 对 `/` 的成功探测打架。未开代理 → 「请先开启本地代理」。

v3.0.1 写入契约未改：**stdin → 暂存 → sha256 → `mv`**。

## 优化

- **Settings 点击 / 聚焦不再跑多主机 WSL curl。** `get_pi_proxy_plan` 只用本机快照（`plan_ui_snapshot`）。实时探测留在「检测代理」和投影路径。
- **发布流水线只打 Windows x64**（`CC-Switch-v*-Windows.msi` + `CC-Switch-v*-Windows-Portable.zip`）。不构建 Linux / macOS / ARM64。

## 自测

云端 harness 把用户拓扑**编码成夹具**（不是连上用户电脑）：

```
WSL 2.7.10, Ubuntu-22.04
networkingMode=mirrored, dnsTunneling=true, firewall=true, autoProxy=false
resolv 10.255.255.254 · default via 172.30.213.1 on eth1 · docker0 linkdown
Windows listen 127.0.0.1:15721 only
curl 127.0.0.1:15721/ → HTTP 404 SUCCESS
172.30.213.1 / 10.255.255.254 → connection refused
```

书面报告：`docs/test-report-v4.1.4-zh.md`（对照 v3.0.1；#19 合入后的 tip）。

**不是「完整自测通过」。** 云端只跑了 Linux `WslRunner` / 夹具 / jsdom。**未安装 MSI，未开 Tauri 窗口，未在用户 PC 上跑 `wsl.exe`。** 场景表一律 **Fixture PASS ≠ 真机已验**。

含 read 修复的 v4.1.5 装上后，在这台 Windows 上点 4 下：

1. **设置 → 检测代理** — 成功 toast，不要 `no route … 127.0.0.1, 172.30.213.1, 10.255.255.254`
2. **启用「百胜」** — 无空 bash；`models.json` 仍有旧供应商 + 新卡，不是空文档
3. **会话页刷新** — 列表能出来
4. **再进设置** — 不要卡 1–9 秒

任一步 FAIL：停用新包，回到 v3.0.1。
