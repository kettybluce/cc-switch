# CC Switch v5.0.0

本仓库独立构建。应用内更新仍然关闭。只发布 **Windows x64**（MSI + 绿色版）。不构建 Linux / macOS / ARM64。

**5.0 的主题：Claude、Codex、Pi 三个客户端在 WSL 里走同一套路径模型和同一个本地代理。** 会话、用量、配置都直接落在发行版家目录（`\\wsl.localhost\Ubuntu-22.04\home\<用户>\.claude` / `.codex` / `.pi`），与开源版 CC Switch 的 WSL 用法一致；不再往 `C:\Users\…\.cc-switch\*-wsl-sessions` 复制任何会话。

外观回到上游 CC Switch（PR #21）：去掉 4.1.0 的 Codex 皮肤（暖色 token、分段控件、重阴影）。用户反馈那套皮肤点击约 1 秒、动画卡顿。

请从 v4.1.6 / v3.0.1 直接升到本页 v5.0.0。

## 修复的问题

- **Pi 会话能看、用量却是 0（PR #23）。** 会话列表原先先用 `wsl.exe` 把 JSONL 镜像到 `%USERPROFILE%\.cc-switch\pi-wsl-sessions`，再 `canonicalize` 成 `\\?\C:\Users\…`；用量扫描只认镜像树，所以「会话管理看得到今天的 Pi 会话，用量统计 $0 / 0 条」。现在会话列表、`pi --session` 恢复命令、用量导入共用 `~/.pi/agent/sessions`（Windows 上是 `\\wsl.localhost\…`），恢复命令回译成发行版内 POSIX 路径并保留大小写。「立即同步」只是再扫同一棵树，不再写 C: 副本。
- **Claude / Codex 在 WSL 里读写不同的文件。** 4.1.x 写 `settings.json` / `auth.json` / `config.toml` 走 `wsl.exe` 落到 WSL home，但接管前的读取、备份、`live 是否已指向当前代理` 判定、`session_index.jsonl` / state db 却读 Windows 的 `C:\Users\…\.claude` / `.codex`。结果是「接管了但 live 没变」「再点接管重建一次」「会话标题对不上」。现在选了 WSL 运行位置后 `~/.claude` / `~/.codex` 统一解析到 `\\wsl.localhost\<发行版>\home\<用户>\…`，读写同一棵树。
- **Claude / Codex 会话与用量也走 C: 镜像。** `wsl-cli-sessions\<发行版>\claude-projects` / `codex-home` 镜像已删除。Claude `~/.claude/projects`、Codex `~/.codex/sessions` + `archived_sessions` 直接在 WSL home 里扫。Codex 归档会话在 WSL 下之前根本不扫，现在扫。
- **配置目录覆盖不允许 `\\wsl.localhost`。** 上游一直允许把 Claude/Codex 配置目录指到 WSL UNC。4.1.x 在后端和设置页都把它丢掉并 toast。现在与 Pi（PR #23）一致：接受 UNC 覆盖，只做 trim。选了 WSL 运行位置时不需要手填，自动就是 WSL home。
- **三个客户端都接本地代理。** 云端 fixture 里对同一个运行中的本地代理（临时端口）依次打开 Claude / Codex / Pi 接管：Claude `settings.json` 的 `ANTHROPIC_BASE_URL`、Codex `config.toml` 的 `[model_providers.*].base_url`、Pi `models.json` 的 `baseUrl`（`/pi/<id>`）都写成 `http://127.0.0.1:<端口>`，关闭后各自恢复真实上游，Pi 顶层 `~/.pi/models.json` 镜像同步。代理地址来自真实 curl 探测（镜像网络 127.0.0.1 优先，HTTP 404 视为可达），不是猜的。

沿用 4.1.x 已修的：镜像网络「检测代理」404 误报、`mktemp` 落到 `/`、Pi `READ_SCRIPT` 丢 `$1` 清空 `models.json`、启用供应商空 bash。写入契约不变：**stdin → 暂存 → sha256 → `mv`**。

## 优化

- **恢复上游 CC Switch 外观（PR #21）。** 回到 v4.0.1 / 上游的 `--primary: 210 100% 56%`、`--radius: 0.5rem`、扁平卡片、标准 muted 控件；去掉 `segmented-control` / `settings-stack` / `shadow-card` / `shadow-float`。功能一律保留：本地代理、WSL 探测、运行位置面板、Windows-only 打包、updater 关闭。
- **运行位置面板显示可直接粘贴到资源管理器的路径。** Claude / Codex 状态行从 `wsl:Ubuntu-22.04:/home/…` 改成 `\\wsl.localhost\Ubuntu-22.04\home\<用户>\.codex\config.toml`。文案不再说「一律 wsl.exe、不用 UNC」，改为说明「读在家目录、写走 wsl.exe、不镜像到 C:」。
- **代码层面统一。** `wsl_cli::claude_wsl_config_dir` / `codex_wsl_config_dir` 与 Pi 的 `local_sessions_root` 共用同一个 `wsl_fs_path`（Windows = UNC，Linux 夹具 = 真实临时 `$HOME`）。`sync_tree` 镜像代码保留但无生产调用。

## 自测

云端 Linux（本发版机器）按 `ci.yml` **Linux 步骤**复跑：

- `pnpm typecheck` / `pnpm format:check` / `pnpm test:unit`（141 文件 / 1130 用例）
- `cargo fmt --check` / `cargo clippy -- -D warnings` / `cargo test`（含 27 条 `pi_runtime::wsl_linux_harness`）

新增 fixture（Linux bash 双、临时 `$HOME`，**不是**连上用户电脑）：

- `claude_and_codex_sessions_and_usage_walk_wsl_home_without_c_mirror` — Claude / Codex 配置目录解析到 WSL home；会话列表各 1 条、用量各导入 1 条；`.cc-switch/wsl-cli-sessions` 与 `pi-wsl-sessions` 都不存在
- `claude_codex_pi_takeover_projects_local_proxy_into_wsl_home` — 真实 curl 探测到临时端口；三个客户端接管后 live 文件都指向 `http://127.0.0.1:<端口>`，关闭后恢复
- `rewrite_proxy_origin_keeps_mirrored_loopback_for_claude_and_codex` — 用户镜像拓扑（mirrored + firewall + dnsTunneling，`127.0.0.1` 404 / `172.30.213.1` 与 `10.255.255.254` 拒绝）下 Claude / Codex 的代理地址保持 `http://127.0.0.1:15721`

**没有**在本 tip 上看到 GitHub Actions 的 `windows-latest` / `macos-latest` 矩阵，也**没有**跑 `backend-windows-wsl2`。这些不声称通过。

**夹具 / harness ≠ 真机 Windows+WSL 冒烟。** 云端没有 `wsl.exe`、没有 `\\wsl.localhost` 9P、没有 MSI 安装、没有 Tauri 窗口。Linux 上 `wsl_fs_path` 用的是真实临时目录，Windows 上才是 UNC；UNC 走 9P 会唤醒发行版，发行版停止时会话/用量列表会为空，这是已知取舍。

v5.0.0 装上后，在 Windows 上点这几下（Ubuntu-22.04 / tfdx8045）：

1. **设置 → 通用** — Claude / Codex / Pi 运行位置都选 WSL Ubuntu-22.04；状态行显示 `\\wsl.localhost\Ubuntu-22.04\home\tfdx8045\…`
2. **设置 → 检测代理** — 成功 toast，不要 `no route …`
3. **分别打开 Claude / Codex / Pi 接管** — 在 WSL 里 `cat ~/.claude/settings.json`、`~/.codex/config.toml`、`~/.pi/agent/models.json`，三者都应指向 `http://127.0.0.1:15721`
4. **会话页** — Claude / Codex / Pi 三个 tab 都能列出今天的会话；Pi 的恢复命令是 `wsl.exe -d Ubuntu-22.04 -- … pi --session '/home/tfdx8045/…'`，不是 `\\?\C:\…`
5. **用量 → 立即同步** — Pi 不再是 $0 / 0 条；`%USERPROFILE%\.cc-switch` 下没有 `pi-wsl-sessions` / `wsl-cli-sessions`
6. **随便改一个供应商并启用** — WSL 里的对应文件立即变化

任一步 FAIL：回退到 v4.1.6 并把日志贴到 issue。
