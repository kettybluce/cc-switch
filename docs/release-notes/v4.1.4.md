# CC Switch v4.1.4

Independent fork hotfix for WSL Ubuntu-22.04 (mirrored + firewall + dnsTunneling). App updater remains disabled. **Windows x64 only.**

Stay on **v3.0.1** until the MSI below is installed. Do not stay on v4.1.3.

## 修复的问题 / Bug fixes

- **检测代理 toast 与 Settings 绿灯不一致 / Detect toast disagreed with Settings.** Settings already showed `http://127.0.0.1:15721` reachable under 镜像网络, but 「检测代理」 toasted `no route from WSL 'Ubuntu-22.04'… (tried 127.0.0.1, 172.30.213.1, 10.255.255.254)`. Detect now uses the same success rule as the probe: any HTTP 1xx–5xx on localhost (including **404** on `/`) is reachable. NAT / dnsTunneling hosts are fallbacks; their connection-refused must not fail the toast when loopback already answered.
- **Pi `models.json` 空 bash / empty bash on provider enable.** Enabling a Pi provider failed with `/bin/bash: line 1: '': No such file or directory` because `wsl.exe -- bash -c` could collapse the script or drop `$1`. Writes now use `wsl.exe -e bash`, reject empty/quote-only scripts, and restore positional args with `set --` so the body is never `''`.
- **Codex / Claude / Pi `mktemp` 打在根目录.** `mktemp` used `"$dir/.cc-switch-XXXXXX"`; an empty `$dir` became `/.cc-switch-XXXXXX`. Atomic writes now stage under `$TMPDIR` or `/tmp` (`mktemp -p` / `mktemp /tmp/cc-switch-XXXXXX`). Empty `$1` or `$1=/` fails as `empty-target` and never mktemps at `/`.
- **代理未开的 toast / proxy-off toast.** A Windows-only `/ping` connection-refused (`Get "http://127.0.0.1:15721/ping"`) no longer fights a working WSL curl to `/`. `/ping` aliases `/health`. A stopped listener toasts 「请先开启本地代理」.

The v3.0.1 write contract is unchanged: **stdin → stage → sha256 → `mv`**. The fallback only restores `$1…` when WSL drops them.

## 优化 / Improvements

- **Settings 点击不再多主机 WSL curl.** `get_pi_proxy_plan` uses a localhost snapshot (`plan_ui_snapshot`). Live multi-host probe stays on 「检测代理」 and on projection. This removes the ~1s focus/click stall from the old 1–9s three-host timeout.
- **Release pipeline is Windows x64 only** (`CC-Switch-v*-Windows.msi` + `CC-Switch-v*-Windows-Portable.zip`). Linux, macOS, and Windows ARM64 are not built.

## 自测 / Self-test

Cloud harness default profile is the user's machine (not generic NAT):

```
WSL 2.7.10, Ubuntu-22.04
networkingMode=mirrored, dnsTunneling=true, firewall=true, autoProxy=false
resolv 10.255.255.254 · default via 172.30.213.1 on eth1 · docker0 linkdown
Windows listen 127.0.0.1:15721 only
curl 127.0.0.1:15721/ → HTTP 404 SUCCESS
172.30.213.1 / 10.255.255.254 → connection refused
```

Covered: detect toast matches localhost 404 success; Settings snapshot does not curl WSL; Pi `models.json` write never runs empty bash when `$1` is dropped; mktemp stays under `/tmp`; 3.0.1 stdin→stage→sha256→`mv` contract still holds.
