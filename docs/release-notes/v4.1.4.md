# CC Switch v4.1.4

本仓库独立构建。应用内更新仍然关闭。只发布 **Windows x64**。

请继续使用 **v3.0.1**，等本页的 MSI 就绪后再装。不要停留在 v4.1.3。

## 修复的问题

- **检测代理 toast 与 Settings 绿灯打架。** Settings 已显示 `http://127.0.0.1:15721` 可达（镜像网络），「检测代理」却 toast `no route from WSL 'Ubuntu-22.04' to CC Switch on port 15721 (tried 127.0.0.1, 172.30.213.1, 10.255.255.254)`。探测与 toast 现用同一规则：本机任意 HTTP 1xx–5xx（含 `/` 上的 **404**）即成功。`172.30.213.1` / `10.255.255.254` 被拒绝只是回退，不能盖过 localhost 成功。
- **启用 Pi 供应商时空 bash。** 启用「百胜」失败：`writing Pi models.json to WSL 'Ubuntu-22.04' failed: /bin/bash: line 1: '': No such file or directory`。现用 `wsl.exe -e bash`，拒绝空脚本，并用 `set --` 补回被丢掉的 `$1`，不再执行 `''`。
- **启用前 `files::read` 丢掉 `$1` 会把现有 `models.json` 当成 missing。** 只给 WRITE 加 `set --` 不够：read 也会把文件判成不存在，再 write 有清空 providers 的风险。READ 现用同样的 `set --` 回退。过程重置审计还发现：启用路径会先 `files::read`；`READ_SCRIPT` 在丢掉 `$1` 时会把现有文件当成 missing，有清空 providers 的风险。read 现与 write 一样用 `set --` 回退。
- **Codex / Claude / Pi 在根目录 mktemp。** `"$dir/.cc-switch-XXXXXX"` 在 `$dir` 为空时变成 `/.cc-switch-XXXXXX`。原子写改为在 `$TMPDIR` 或 `/tmp` 下 `mktemp`。空目标报 `empty-target`，绝不在 `/` 建临时文件。
- **代理未开的 toast。** Windows 侧单独打 `/ping` 被拒绝时，不再和 WSL 里对 `/` 的成功探测打架。监听未开时 toast「请先开启本地代理」。

v3.0.1 写入契约未改：**stdin → 暂存 → sha256 → `mv`**。

## 优化

- **Settings 点击 / 聚焦不再跑多主机 WSL curl。** `get_pi_proxy_plan` 只用本机快照（`plan_ui_snapshot`）。实时探测留在「检测代理」和投影路径，避免原来 1–9 秒三主机超时造成的点击卡顿。
- **发布流水线只打 Windows x64**（`CC-Switch-v*-Windows.msi` + `CC-Switch-v*-Windows-Portable.zip`）。不再构建 Linux / macOS / ARM64。

## 自测

云端 harness 默认配置就是这台机器（不是泛化 NAT）：

```
WSL 2.7.10, Ubuntu-22.04
networkingMode=mirrored, dnsTunneling=true, firewall=true, autoProxy=false
resolv 10.255.255.254 · default via 172.30.213.1 on eth1 · docker0 linkdown
Windows listen 127.0.0.1:15721 only
curl 127.0.0.1:15721/ → HTTP 404 SUCCESS
172.30.213.1 / 10.255.255.254 → connection refused
```

书面报告：`docs/test-report-v4.1.4-zh.md`（过程重置；对照 v3.0.1）。场景表全部 **PASS**。

`user_mirrored_firewall_dnstunnel_e2e_self_test` + `enable_pi_provider_on_user_topology_survives_dropped_argv` + `plan_ui_snapshot_never_invokes_wsl_runner`：detect toast 与 localhost 404 一致；Settings 快照不 curl WSL；启用「百胜」走完整 switch→read→write；mktemp 只在 `/tmp`；3.0.1 写入契约仍成立。`cargo test --lib pi_runtime::` 131 项 + `wsl_cli::` 4 项已通过。
