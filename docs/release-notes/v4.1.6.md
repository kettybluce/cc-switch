# CC Switch v4.1.6

本仓库独立构建。应用内更新仍然关闭。只发布 **Windows x64**。

**不要装旧的 v4.1.4。** 那一包没有 `READ_SCRIPT` 的 `set --` 回退：启用 Pi 供应商时若 WSL 丢掉 `$1`，会把现有 `models.json` 当成 missing，有清空 providers 的风险。

**请用本页的 v4.1.6，不要停在 v4.1.5。** v4.1.5 缺随后两笔 CI 修复（`cargo fmt --check`、clippy `-D warnings`）。功能与 v4.1.5 相同，包装车点在含 fmt/clippy 的 tip。

请继续使用 **v3.0.1**，等本页的 v4.1.6 MSI 就绪后再装。不要停留在 v4.1.3。

相对 v3.0.1 的 4.1.x 回归（检测代理误报、根目录 mktemp、启用清空、设置卡顿）都在这包里。

## 修复的问题

- **镜像网络下「检测代理」把 404 当成失败。** Settings 已显示 `http://127.0.0.1:15721` 绿灯（mirrored），点「检测代理」却 toast `no route from WSL 'Ubuntu-22.04' to CC Switch on port 15721 (tried 127.0.0.1, 172.30.213.1, 10.255.255.254)`。探测与 toast 现用同一规则：本机任意 HTTP 1xx–5xx（含 `/` 上的 **404**）即成功。`172.30.213.1` / `10.255.255.254` 被拒绝只是回退，不能盖过 localhost 成功。
- **Codex / Claude / Pi 在根目录 mktemp。** `"$dir/.cc-switch-XXXXXX"` 在 `$dir` 为空时变成 `/.cc-switch-XXXXXX`。原子写改为在 `$TMPDIR` 或 `/tmp` 下 `mktemp`。空目标报 `empty-target`，绝不在 `/` 建临时文件。
- **Pi `READ_SCRIPT` 丢掉 `$1` 会清空 `providers` / `models.json`。** 启用「百胜」走 `switch` → read → write。只给 WRITE 加 `set --` 不够：`READ_SCRIPT` 仍读 `$1`；空 `$1` 时 `[ ! -e "$1" ]` 当成 missing，再 write 可能写出空文档。v4.1.5 起 read 与 write 一样用 `set --` 补回路径。
- **启用 Pi 供应商时空 bash。** `writing Pi models.json … /bin/bash: line 1: '': No such file or directory`。现用 `wsl.exe -e bash`，拒绝空脚本。
- **代理未开的 toast。** Windows 单独打 `/ping` 不再和 WSL 对 `/` 的成功探测打架。未开代理 → 「请先开启本地代理」。

v3.0.1 写入契约未改：**stdin → 暂存 → sha256 → `mv`**。UNC 路径仍拒绝。Claude / Codex / Pi 一律 `wsl.exe` + 本地代理。应用内更新仍关闭。

## 优化

- **通用设置里 Claude / Codex 与 Pi 并列的运行位置。** Settings → 通用：三个运行位置走同一套 WSL 发行版 + 本地代理，不再各写一套路径。
- **相对 4.1.0 的点击卡顿。** Settings 点击 / 聚焦不再跑多主机 WSL curl。`get_pi_proxy_plan` 只用本机快照（`plan_ui_snapshot`）。实时探测留在「检测代理」和投影路径，避免原来 1–9 秒三主机超时。
- **CI：本 tip 已 `cargo fmt` + clippy 干净。** `02f10007` 补 fmt；`38c69318` 把测试专用 helper 收到 `cfg(test)` 并改用 `Result::ok`，满足 `-D warnings`。这是相对 v4.1.5 的包装车差。
- **发布流水线只打 Windows x64**（`CC-Switch-v*-Windows.msi` + `CC-Switch-v*-Windows-Portable.zip`）。不构建 Linux / macOS / ARM64。
