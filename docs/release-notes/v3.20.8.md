# CC Switch v3.20.8

本仓库独立构建，基于官方 **3.20.x**（含已合并 PR #35）。只发布 **Windows x64**（MSI + 绿色版）。不构建 Linux / macOS / ARM64。

**请优先使用绿色版（Portable）。** MSI 若在安装/升级时出现 Error 5（拒绝访问 `D:\Config.Msi` 或系统盘 `Config.Msi`），这是 Windows Installer 回滚缓存 ACL，per-user 安装包无法修复。说明见 [windows-msi-error-5-zh.md](../windows-msi-error-5-zh.md)。

**SCHEMA 仍为 18。** 没有 `migrate_v18_to_v19`、没有新表、没有改 `proxy_config` CHECK。官方 3.20.2 仍能打开这个库文件。

请从本仓库 v3.20.7（或官方 3.20.2 + 本 fork main）升到本页 v3.20.8。

## 修复的问题

- **百胜 1214「角色信息不正确」。** 保存或打开 Pi 供应商列表时，自动为 CC Switch 管理的 `openai-completions` 卡（provider + 每个 model）补 `compat.supportsDeveloperRole: false`，让 Pi 把系统提示只写成 `system`，不再写成 `developer`。接管投影同样写入。显式 `true`（官方 OpenAI）不覆盖。Live 文件是 `~/.pi/agent/models.json`，不是 `~/.pi/models.json`。
- **代理兜底。** Chat Completions 出站把 `messages[].role=developer` 改成 `system`。不改 Responses `input[]`，不把 prompt 写进 `user`。Anthropic 透传只把 `developer` 提到顶层 `system`。

## 优化

- **SCHEMA 18，可切回官方。** 无库迁移。
- **Windows-only 打包。** 与 v3.20.7 相同：tag 触发只出 MSI + 绿色版。

装上 v3.20.8 后请自己点：

1. 打开 CC Switch **Pi 供应商列表**（或保存/重新接管百胜）
2. 打开 **`~/.pi/agent/models.json`**，确认 baisheng 及其三张模型都有 `"supportsDeveloperRole": false`
3. 再调 yum：`http://api.llm.prd.yumc.local/v1`，不应再出现 1214
4. OpenCode Go / fengwind 行为不变；MSI Error 5 → 改用绿色版 zip，解压运行 `CC-Switch.exe`

任一步 FAIL：把日志贴到 issue。SCHEMA 没升，回退 v3.20.7 / 官方 3.20.2 是安全的。
