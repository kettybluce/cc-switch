# CC Switch v3.20.6

本仓库独立构建，基于官方 **3.20.x**（含已合并 PR #31）。只发布 **Windows x64**（MSI + 绿色版）。不构建 Linux / macOS / ARM64。

**请优先使用绿色版（Portable）。** MSI 若在安装/升级时出现 Error 5（拒绝访问 `D:\Config.Msi` 或系统盘 `Config.Msi`），这是 Windows Installer 回滚缓存 ACL，per-user 安装包无法修复。说明见 [windows-msi-error-5-zh.md](../windows-msi-error-5-zh.md)。

**SCHEMA 仍为 18。** 没有 `migrate_v18_to_v19`、没有新表、没有改 `proxy_config` CHECK。官方 3.20.2 仍能打开这个库文件。

请从本仓库 v3.20.5（或官方 3.20.2 + 本 fork main）升到本页 v3.20.6。

## 修复的问题

- **会话复制改为 pi --session &lt;会话id&gt;。** 会话管理器「复制恢复命令」不再复制 jsonl 文件路径（包括 Windows 规范化后的 `\\?\UNC\wsl.localhost\…`）。改为官方 Pi UX：`pi --session <会话id>`，id 来自会话 JSONL 头。Pi CLI 的 `--session <path|id>` 按精确 id / 前缀 UUID 解析。与 Claude（`claude --resume <id>`）、Codex（`codex resume <id>`）一致。

## 优化

- **SCHEMA 18，可切回官方。** 无库迁移。
- **Windows-only 打包。** 与 v3.20.5 相同：tag 触发只出 MSI + 绿色版。

## 自测

PR #31 tip `27b7c491` 的 GitHub Actions 全绿：

- Frontend Checks — skipped（未改前端）
- Backend Checks (ubuntu-22.04) — pass
- Backend Checks (macos-latest) — pass
- Backend Checks (windows-latest) — pass
- Backend Checks (Windows + WSL2 home) — pass

云端 Linux 另记：`cargo test --lib session_manager::providers::pi`（14 用例，含 `resume_command_uses_session_id_not_file_path`）。

**云端测试 ≠ 真机 Windows 冒烟。** 没有在用户电脑上点过会话复制或 MSI 安装。Actions `windows-latest` / WSL2 是 cargo 检查，不是装包冒烟。

装上 v3.20.6 后请自己点：

1. 打开会话管理器，选一条 Pi 会话 → 「复制恢复命令」应为 `pi --session <该会话 UUID/id>`，不是 UNC 或 jsonl 路径
2. 在 WSL 或 Windows 终端粘贴执行，Pi 应按 id 打开对应会话
3. Claude / Codex 的复制命令仍是原来的 id 形式
4. MSI Error 5 → 改用绿色版 zip，解压运行 `CC-Switch.exe`

任一步 FAIL：把日志贴到 issue。SCHEMA 没升，回退 v3.20.5 / 官方 3.20.2 是安全的。
