## 修复的问题

- **接管 fail-closed**（#53 / #60）：Claude/Codex/Pi Live 已指向**另一**本地代理，或 Live 文件缺失/损坏时，enable 必须报错；Live 原样，无 backup、无接管标志
- **密钥脱敏**（#61）：上游 401 体、Usage 请求日志、托盘 plan/错误、`crash.log`、Pi session `errorMessage`、Codex 错误 JSON、`AuthInfo` Debug、前端请求详情不再落盘/展示完整 `sk-` / `sk-ant-` 密钥。Pi `models.json` 投影仍用 `PROXY_MANAGED`
- **v13 CHECK 启动**：给尚无 `grokbuild` 的旧 CHECK 表 seed 该行时改为跳过，交给 `migrate_v13_to_v14` 重建，避免启动失败（#63）

## 自测

云端 Linux / GitHub Actions：`pnpm typecheck` / `format:check` / `test:unit`；`cargo fmt` / `clippy` / 相关 `cargo test`（含 `proxy_projection_linux`、SCHEMA 18 护栏）。`bash scripts/ci/lint-shell-and-workflows.sh` 与 `bash scripts/ci/dry-run-windows-portable.sh`（#55，不编译 Tauri）。不写用户 `C:` 数据。

本云端 **无 Docker daemon**，未能在本机跑 `pnpm test:docker:all`。#47 默认夹具仍是最低门槛；#50 要求的全量报告需在有 Docker 的机器上补齐。#54/#49（默认全量并落盘报告）**尚未合入**。

**云端测试 ≠ 真机 Windows / macOS 冒烟。** 没有在用户电脑上走 Claude/Codex/Pi CLI 或 MSI / DMG 安装。Actions `windows-latest` / WSL2 / `macos-latest` 是编译检查，不是装包冒烟。

装上 v3.20.14 后请自己点：

1. Claude / Codex / Pi：Live 已指向其他本地代理时开启接管应失败，Live 不被改写
2. 缺 `settings.json` / `config.toml` / 损坏 `models.json` 时 enable 应报错，无 backup
3. 请求日志、托盘、crash.log、请求详情不应出现完整 API Key
4. 四语设置里「一键安装」键齐全；已有 Pi `cc-switch-*` live 键不被改写；Cursor 池默认仍为 `gpt-5.6-sol`
5. MSI Error 5 → 改用绿色版 zip（解压后 `cc-switch.exe` 旁应有 `portable.ini`）
6. 账号默认 / Cursor 池模型行为与 3.20.13 相同
7. **本版没有 #56**：DeepSeek 非 object JSON unwrap、截断 SSE 用量冲刷、4xx/5xx 对齐若仍复现，等后续合入 #56 的版本

任一步 FAIL：把日志贴到 issue。SCHEMA 没升，回退 v3.20.13 / v3.20.12 / 官方 3.20.2 是安全的。
