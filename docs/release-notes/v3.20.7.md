# CC Switch v3.20.7

本仓库独立构建，基于官方 **3.20.x**（含已合并 PR #33）。只发布 **Windows x64**（MSI + 绿色版）。不构建 Linux / macOS / ARM64。

**请优先使用绿色版（Portable）。** MSI 若在安装/升级时出现 Error 5（拒绝访问 `D:\Config.Msi` 或系统盘 `Config.Msi`），这是 Windows Installer 回滚缓存 ACL，per-user 安装包无法修复。说明见 [windows-msi-error-5-zh.md](../windows-msi-error-5-zh.md)。

**SCHEMA 仍为 18。** 没有 `migrate_v18_to_v19`、没有新表、没有改 `proxy_config` CHECK。官方 3.20.2 仍能打开这个库文件。

请从本仓库 v3.20.6（或官方 3.20.2 + 本 fork main）升到本页 v3.20.7。

## 修复的问题

- **Pi 接管后按 Pi 供应商选路，修复误用 Claude 导致 500。** 打开 Pi 本地代理接管后，`models.json` 仍投影到现有 Claude listen，并带 `x-cc-switch-app: pi`。此前代理仍按 Claude / Codex **当前供应商**转发，凭证对不上，请求 500。现在识别该头后选用可转发的 Pi 目录供应商（真实 `apiKey` / `baseUrl`），按 listen 路由匹配 `api`（Anthropic → Claude、OpenAI → Codex、Gemini → Gemini），跳过 `PROXY_MANAGED` 投影占位。不升 SCHEMA，不开独立 Pi 网关，不写 `defaultProvider` / `defaultModel`，不碰 `auth.json`。

## 优化

- **SCHEMA 18，可切回官方。** 无库迁移。
- **Windows-only 打包。** 与 v3.20.6 相同：tag 触发只出 MSI + 绿色版。

- Backend Checks (ubuntu-22.04) — pass
- Backend Checks (macos-latest) — pass

云端 Linux 另记：`cargo fmt --check` / `clippy -D warnings`；`pi_header_selects` / `pi_selection_` / `extract_base_url_from_pi_native` / `pi_takeover_projects` / `provider_router` 映射用例通过。`SCHEMA_VERSION == 18`，`proxy_config` 无 `pi` 行。

**云端测试 ≠ 真机 Windows 冒烟。** 没有在用户电脑上走 Pi CLI 或 MSI 安装。Actions `windows-latest` / WSL2 是 cargo 检查，不是装包冒烟。

装上 v3.20.7 后请自己点：

1. **Pi 页打开接管** — `models.json` 各 provider 的 `baseUrl` 指向 Claude listen；发一条 Pi 请求应成功，不应再因走 Claude/Codex 当前卡而 500
2. **用量** — 新请求记 `app_type=pi`
3. **关掉接管** — `models.json` 恢复真实上游；`auth.json` 与 defaultProvider / defaultModel 不变
4. MSI Error 5 → 改用绿色版 zip，解压运行 `CC-Switch.exe`

任一步 FAIL：把日志贴到 issue。SCHEMA 没升，回退 v3.20.6 / 官方 3.20.2 是安全的。
